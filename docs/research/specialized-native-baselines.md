# DFloat11 / ECF8 native-conversion protocol

DFloat11 and ECF8 are recorded as checkpoint-level native model conversions,
not as generic byte-stream codecs. Their rows therefore use the following
frozen scope:

| Field | Frozen value |
| --- | --- |
| Input | Tensors in the checkpoint `download-manifest.json` |
| Output | The converter's native model directory |
| Exactness target | Tensor payload bits after decoding |
| Original safetensors byte exact | No |
| Stand-alone offline decompression command | Not available in this harness |
| Timed region | Conversion including the official correctness check |

The official checks currently provide elementwise value-equality evidence.
They do not independently compare decoded tensor payload bytes against the
manifest input. Consequently, a successful run is useful for an exploratory
native-format size table, but its raw record remains
`publication_ready=false`. Do not describe it as original-file byte-exact or
as independently established tensor-bit-exact until an independent decoder
and payload comparison has also passed.

The frozen adapters are:

| Method | Official commit | Models | Workers |
| --- | --- | --- | ---: |
| DFloat11 | `457733886ce6ebc6d8dda1621fad1ffa2661e028` | Llama 3.1 8B BF16, Qwen3 32B BF16, Llama 3.1 70B BF16 | 1 |
| ECF8 | `9cbf3d5cf77d6db8cf6f29df1fe6d52bc88fa01e` | Qwen3 32B FP8 | 16 |

DFloat11's wrapper loop is serial; its worker value only controls Torch/OMP
threading. ECF8's official entry point explicitly uses 16 processes. These
values are part of the config schema and run identity. The DFloat11 checkout
declares Apache-2.0. No license file was observed in the pinned ECF8 checkout,
so the preflight emits a publication/redistribution warning.

## Prepare and check

Copy
[`configs/specialized-baselines.example.json`](../../configs/specialized-baselines.example.json)
and adjust only installation paths if needed. Keep the commits, checkpoint
sets, worker counts, and protocol fields unchanged.

Run the read-only preflight before starting a converter:

```bash
python3 scripts/preflight_specialized_baselines.py \
  --config /path/to/specialized-baselines.json \
  --models-root /workspace/checkpoints
```

The preflight:

- verifies the fixed checkout commits and isolated Python environments;
- checks the exact supported checkpoint set and frozen model revisions;
- reads only safetensors headers and file sizes, not tensor payloads;
- requires BF16-only input for DFloat11 and Qwen3 E4M3 FP8/BF16 input for
  ECF8;
- checks model config and, for ECF8, tokenizer assets;
- warns that the official value-equality check is not an independent bitwise
  validation.

`--skip-runtime` omits checkout/environment checks for metadata-only testing.
`--publication-ready` deliberately turns the missing independent bitwise
validation warning into an error. It will fail with the current official-only
protocol; this is a guardrail, not a converter failure.

The current downloaded weight directories may lack `config.json` and tokenizer
files. Those small support assets must be fetched at the same frozen model
revision before conversion; no replacement or duplicate model weights are
needed.

### Validated DFloat11 runtime

The pinned DFloat11 checkout was validated with Python 3.12.13,
Torch 2.13.0+cu130, CUDA driver 13.1, and an RTX 5090 (`sm_120`). Its bundled
PTX was generated by CUDA 12.2 for `sm_52`; the CUDA driver successfully
JIT-loaded it on `sm_120`. The direct Python dependency lock is
`configs/dfloat11-runtime.requirements.txt`.

```bash
git clone --filter=blob:none \
  https://github.com/LeanModels/DFloat11.git /opt/DFloat11
git -C /opt/DFloat11 checkout --detach \
  457733886ce6ebc6d8dda1621fad1ffa2661e028

/venv/main/bin/python3 -m venv --system-site-packages /opt/dfloat11-venv
/opt/dfloat11-venv/bin/python -m pip install \
  -r configs/dfloat11-runtime.requirements.txt
/opt/dfloat11-venv/bin/python -m pip install \
  --no-deps --editable /opt/DFloat11
/opt/dfloat11-venv/bin/python -m pip check
```

The environment deliberately uses Setuptools 80.9.0. Setuptools 82 no longer
provides `pkg_resources`, which the pinned DFloat11 source imports at module
initialization. This pin avoids modifying the official checkout. DFloat11
still emits a deprecation warning for that API; removing the pin would require
a separately documented upstream adapter patch.

Lightweight validation used no downloaded checkpoint weights. A 4,096-element
synthetic BF16 module passed the official CUDA decode check and Compute
Sanitizer memcheck with zero errors. Tiny one-layer Llama and Qwen3 checkpoints
also completed the full repository adapter CLI; each exercised embedding,
decoder-block, and LM-head conversion. These smokes establish runtime and
adapter compatibility only, not publication-level independent bitwise
validation of the real checkpoints.

## Independent DFloat11 / ECF8 tensor-bit validation

After a real conversion has completely finished, run the independent validator
against the canonical source checkpoint and native output directory:

```bash
python3 scripts/validate_specialized_bits.py dfloat11 \
  --source /workspace/checkpoints/llama-3.1-8b-bf16 \
  --converted \
    results/specialized-native/archives/llama-3.1-8b-bf16/dfloat11.brv \
  --report \
    results/specialized-native/dfloat11-llama-3.1-8b-bit-validation.json
```

For ECF8:

```bash
python3 scripts/validate_specialized_bits.py ecf8 \
  --source /workspace/checkpoints/qwen3-32b-fp8 \
  --converted \
    results/specialized-native/archives/qwen3-32b-fp8/ecf8.brv \
  --report \
    results/specialized-native/ecf8-qwen3-32b-fp8-bit-validation.json
```

The validator does not import either upstream package or call an official CUDA
decoder. It compiles the small independent C decoder in
`scripts/dfloat11_cpu_decoder.c` and sequentially decodes each Huffman exponent
stream on CPU. DFloat11 reconstruction is compared as raw BF16 `uint16`
patterns. ECF8 reconstruction is compared as raw E4M3 `uint8` patterns,
including sign, exponent, and mantissa bits. Every tensor stored directly in
the converted checkpoint (including ECF8 scale and normalization tensors) is
compared as raw bytes. Decoding and comparison use bounded chunks; checkpoint
and artifact safetensors remain memory-mapped. A host C compiler (`cc`) is
required; no GPU is used.

Success exits zero and writes a report with `exact=true`, validator and decoder
hashes, frozen source revision, tensor counts, and compared bytes. It hashes
every source and converted safetensors file, verifies source sizes and SHA256
values against `download-manifest.json`, and records hashes for the native
config/pattern files. A mismatch, truncated stream, invalid LUT, missing or
unclassified tensor, changed shape/dtype, or incorrect split boundary exits
nonzero and records the first detected failure. It also checks the native
parallel-decoder metadata shapes, endpoint/monotonicity constraints, and
zero-padding for unused threads. The validator never edits `runs.jsonl`;
preserve its JSON report as separate publication evidence or explicitly ingest
it in a later result-schema update.

Limitations:

- run it only after conversion has exited successfully; a partially written
  native directory is expected to fail;
- it verifies manifest weight tensor bit patterns, not tokenizer/config file
  bytes or model-level inference behavior;
- the decoder targets only the pinned DFloat11 0.5.0 and ECF8 0.2.0 native
  layouts with 8 bytes/thread and 512 threads/block;
- it logically decodes the Huffman payload and structurally validates
  `gaps`/`output_positions`, but does not verify used-thread gap values or
  independently recompute intermediate block positions; retain the converter's
  official CUDA check as necessary runnable-artifact evidence alongside the
  independent logical tensor-bit report;
- validation time is outside conversion timing and must not be reported as
  decompression throughput;
- validation and file hashing read the complete source and converted payloads,
  warming filesystem cache; run timed compression/decompression measurements
  first, or reapply their declared cache protocol afterward.

## Interpreting time and throughput

The raw `wall_seconds` and `throughput_bytes_per_second` fields measure native
conversion plus the in-process official validation. They must not be merged
with generic codec compression throughput. Neither adapter currently exposes
a comparable stand-alone decompression operation, so decompression time and
throughput remain unreported rather than inferred from model loading.

The full DFloat11 runtime preflight imports the package and therefore JIT-loads
the bundled PTX before the measured conversion. Subsequent runs should be
reported as using a warm driver JIT cache. A cold-JIT experiment needs a
separate CUDA cache directory and must be labeled separately; it must not be
mixed into repeated conversion timing.

For a later paper table, present these rows as “native conversion (official
validation included)” in a separate panel and retain the independent
tensor-bit report as validation evidence. A comparable stand-alone decode
timing command is still absent. Any change to the timed boundary or validation
evidence must produce a new protocol config and therefore a new run ID.
