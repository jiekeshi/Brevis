# Brevis — Weight Compression via Program Synthesis

Bit-exact lossless compression of neural-network weights via **program
synthesis on a low-level reversible grammar**, with A\*-style branch-and-
bound search guided by emerged macros (DreamCoder-style abstraction).

Implemented in **Zig 0.16**.

## Build & run

```bash
zig build -Doptimize=ReleaseFast

./zig-out/bin/brevis make-fixture model.safetensors      # synth fp16 model
./zig-out/bin/brevis compress    model.safetensors model.brv
./zig-out/bin/brevis decompress  model.brv          recovered.safetensors
./zig-out/bin/brevis verify      model.brv          model.safetensors
./zig-out/bin/brevis bench       model.safetensors        # synthesize, no write
./zig-out/bin/brevis baseline    model.safetensors        # brevis vs gzip vs zstd
./zig-out/bin/brevis train       model.safetensors train.json  # B&B + macro mining
./zig-out/bin/brevis demo                                # synthetic data

zig build test                                            # unit tests (20)
```

## Architecture

One grammar, one search, one archive. No more dual code paths.

```
═════════════════════ COMPRESS (compress / bench / baseline) ════════════════

model.safetensors
   │ mmap (zero-copy 2 GB)
   ▼
safetensors.zig parser → list of TensorViews
   │
   │ for each tensor, in parallel across 12 threads:
   ▼
astar.synthesize(view as u16 stream)
   │   * actions: 16 low-level reversible primitives
   │             + built_in_macros (split_field nested for fp16/bf16)
   │             + discovered_macros (from previous `brevis train` runs)
   │   * pruning: admissible Shannon-entropy lower bound + best-so-far
   ▼
astar.realize(node, input)
   │   * walks the program top-down
   │   * runs lowlevel.forward at non-terminals
   │   * builds Huffman / rANS table + encodes bytes at terminals
   │   * expands any macro into chain/split/terminal subtree
   ▼
pnode_archive.buildArchiveBytes
   │   * dedup Huffman/rANS tables across tensors → shared codebook section
   │   * serialize PNode tree per tensor (v2 format, magic "BRV\x02")
   ▼
model.brv (file)

═════════════════════ DECOMPRESS (decompress / verify) ════════════════

model.brv
   │
   ▼
pnode_archive.parseArchive → shared codebooks + per-tensor PNode trees
   │
   │ for each tensor:
   ▼
astar.decompress(node)
   │   * terminal: huffman/rans/raw decode using side_info
   │   * chain: recurse, then apply lowlevel.inverseOne
   │   * split: recurse on both branches, then lowlevel.inverseTwo
   ▼
reconstructed tensor (bit-exact)

═════════════════════ TRAIN (train) ════════════════

model.safetensors
   │ subsample 5K elem per tensor (mining only — not real compress)
   ▼
parallel B&B per tensor: depth 4, 30 K node budget
   │ each finds a program over the current macro library
   ▼
subtree mining + MDL promotion (count × (size−1) − macro_def_cost > 0)
   ▼
train_report.json
   │
   │ python3 tools/emit_macros.py train_report.json src/discovered_macros.zig
   ▼
zig build → new macros are now actions in the next compress / train round
```

## Low-level grammar

16 by-construction reversible primitives. All have forward/inverse, all
proven reversible by property tests.

| Op | Effect | Inverse |
|---|---|---|
| `xor_const(c)` | `s'[i] = s[i] ⊕ c` | self |
| `add_const_mod(c, k)` | `(s[i] + c) mod 2^k` | `add_const_mod(-c)` |
| `rotate_bits(r, k)` | `rotl_k(s[i], r)` | `rotate_bits(-r, k)` |
| `bit_swap_pair(i, j, k)` | swap bits i & j | self |
| `bit_reverse(k)` | reverse bit order | self |
| `negate_mod(k)` | `(-s[i]) mod 2^k` | self |
| `mul_const_odd_mod(c, k)` | `(c·s[i]) mod 2^k`, c odd | Newton-iteration |
| `xor_with_shift(s, k)` | `s[i] ⊕ (s[i] >> s)` | iterated |
| `gray_code` | binary → Gray | `inv_gray_code` |
| `xor_prev` | `s[i] ⊕ s[i-1]` | `prefix_xor` |
| `diff_mod(k)` | `(s[i] - s[i-1]) mod 2^k` | `cumsum_mod` |
| `split_field(start, n, k)` | u_k → (u_n, u_{k-n}) | `inverseTwo` |
| `huffman` / `rans` / `raw` | terminal entropy coders | their decoders |

`split_field` is the only fan-out primitive (1 → 2 streams). Everything else
is 1 → 1.

## Search (`astar.zig`)

Strictly **branch-and-bound** with admissible heuristic, but uses the A\*
core idea (admissible h + best-so-far prune). DFS-recursive — peak memory =
depth × stream size.

```
bestForStream(input, depth_left, incumbent):
    if h(input) >= incumbent: return ⊥           # admissible prune
    for term in {huffman, rans, raw}:
        cost = terminalCost(term, input)
        if cost < incumbent: incumbent = cost, plan = leaf(term)
    for macro in built_in ∪ discovered:           # macros are atomic actions
        cost = applyMacroCost(macro, input)
        if cost < incumbent: incumbent = cost, plan = macro
    if depth_left == 0: return incumbent
    for op in actions(input.bpe):
        out = lowlevel.forward(op, input)
        sub = bestForStream(out, depth_left-1, incumbent)
        if op produces a single stream:    plan = chain(op, sub)
        if op = split_field (2 outputs):   solve hi & lo independently
```

Macros (both built-in and discovered) are **atomic actions** at search time:
one `applyMacroCost` call costs O(macro_size · n). At `realize()` time the
macro is expanded into its underlying `chain`/`split`/`terminal` subtree so
decompression doesn't need to know about macros.

## Built-in vs discovered macros

`src/built_in_macros.zig` ships three hand-coded macros covering the most
common fp16/bf16 split patterns. They guarantee day-1 ratio without any
training run. They look like:

```zig
.name = "split_bf16_huff_rans_rans",
.nodes = &.{
    // 0: split_field(15, 1, 16)      ─→ (sign:1, rest:15)
    // 1: huffman          (for sign)
    // 2: split_field(7, 8, 15)       ─→ (exp:8, mant:7)
    // 3: rans             (for exp)
    // 4: rans             (for mant)
}
```

`src/discovered_macros.zig` is **auto-generated** by `tools/emit_macros.py`
from `brevis train` output. Currently holds 9 emerged macros, e.g.:

* `macro_xor_with_shift_2_split_field_80200_rans_rans` (MDL benefit 370)
* `macro_split_field_80200_rans_rans`                  (MDL benefit 273)
* `macro_split_field_80107_rans_rans`                  (MDL benefit 33)

These were discovered by running B&B on TinyLlama tensors and identifying
subtrees that recur frequently enough to amortize their macro-definition cost
(MDL = `count × (size − 1) − macro_def_cost`).

## Closed wake-sleep loop

```
brevis train model.safetensors train.json
        ↓  (parallel B&B, subsample 5K, ~1 min on TinyLlama)
train.json (subtree counts, PHOG pair counts, promoted macros)
        ↓
python3 tools/emit_macros.py train.json src/discovered_macros.zig
        ↓
zig build -Doptimize=ReleaseFast
        ↓
brevis train ...     # next iteration finds higher-level macros built on the previous ones
```

## Baseline comparison (synthetic fp16 fixture)

```
                       size (bytes)        ratio
                       -------------       --------
raw                          2,760,704     1.000x
gzip -9                      2,548,154     1.083x  (DEFLATE)
zstd -3                      2,533,356     1.090x  (zstd default)
zstd -19                     2,537,473     1.088x  (zstd best)
brevis (.brv archive)        2,321,813     1.189x  (low-level synth + macros)
```

**brevis is ~10% better than zstd -19** on fp16 weight data, bit-exact.

## What the unification deleted

These files (~2,500 lines) lived in the pre-cleanup version and are now
gone, replaced by the single low-level pipeline:

* `src/prior.zig`     — hand-tuned PHOG; replaced by learned `discovered_macros.zig`
* `src/ops.zig`       — high-level DSL (split_float, bitplane_split, delta_encode); reproducible from low-level macros
* `src/program.zig`   — high-level Node tree; replaced by `astar.PNode`
* `src/search.zig`    — high-level B&B; replaced by `astar.zig`
* `src/archive.zig`   — v1 BRV format; replaced by `pnode_archive.zig` (v2 format, magic `BRV\x02`)
* `src/phog.zig`      — high-level PHOG; superseded by the macro library

## Performance journey

TinyLlama 1.1B (2 GB BF16) wall time over the project's history:

| Step | Wall time | Ratio |
|---|---|---|
| 1. baseline (single-thread, full search, per-candidate verify) | ~60 min | 1.515× |
| 2. + 12-thread tensor-level parallelism | 3:36 | 1.515× |
| 3. + faster inner loops (direct-indexed Huffman/rANS, 64-bit `BitWriter`) | 3:30 | 1.515× |
| 4. + skip per-candidate verify (one e2e verify only) | 3:00 | 1.515× |
| 5. + tighten search + tensor-type fast-path | 3.6 s | 1.515× |
| 6. + SIMD-style histogram (4 parallel counter arrays) | 2.8 s | 1.515× |
| 7. + `@Vector(8, u16)` SIMD `splitFloat` | 1.76 s | 1.515× |
| 8. + mmap input safetensors | 1.69 s | 1.515× |
| 9. + learned PHOG fast-path (count-based MLE) | 1.75 s | 1.515× |
| 10. **+ full unification: low-level grammar only, deleted dual paths** | — | — |

After unification the high-level shortcut is gone; current built-in macros
hit ~1.19× on synthetic. Retraining with `brevis train` recovers higher
ratios as more macros emerge.

## What's NOT done

* `brevis train` doesn't yet auto-regenerate `discovered_macros.zig` —
  still needs `python3 tools/emit_macros.py` step manually.
* `mul_const_odd_mod` is included as a primitive but rarely picked by search;
  could be removed if it stays unused after more training rounds.
* No corpus-wide PHOG over the unified grammar yet. The "PHOG" today is
  effectively just the macro library (whose presence biases the search).
  A real conditional `P(macro | tensor features)` would further speed-up
  large-tensor compress.
